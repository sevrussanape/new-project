# Architecture

```text
Browser UI (web/index.html)
        |
        | loopback HTTP / JSON
        v
studio.py (local server + API)
        |                 \
        |                  +--> hardware_scanner.py --> model_selector.py
        v
engine/job_manager.py (single background worker)
        |
        +--> engine/video_engine.py
                 |-- LTXRuntime: PyTorch + Diffusers in-process (eligible CUDA GPUs)
                 |-- Image Motion: Pillow frames + imageio-ffmpeg (low-VRAM fallback)
        |
        v
outputs/*.mp4 --> browser preview
```

## Design decisions

- One local Python process owns the web API and job queue; there is no second workflow/model server.
- GPU/model dependencies are optional at application startup. The Studio still opens without PyTorch or LTX weights.
- The hardware scanner is side-effect free. It gathers OS, RAM, disk, NVIDIA telemetry and optional PyTorch CUDA facts.
- The model selector is explainable, deterministic policy code. It recommends only a model integrated into the runtime and checks current free VRAM.
- The runtime performs its own capability gate immediately before model loading. The UI's disabled state is not the only safety check.
- Jobs run sequentially to reduce VRAM pressure. Each job exposes status, progress, cancellation and output path.
- Low-VRAM Image Motion is explicitly not classified as generative AI. This avoids misleading portfolio claims and gives constrained PCs a real working output path.

## LTX runtime boundary

LTX is loaded lazily with `LTXPipeline.from_pretrained`. The runtime uses CUDA only, selects BF16 only when PyTorch reports support and otherwise uses FP16, enables model CPU offload, and enables VAE tiling when supported. The published legacy Diffusers example reports about 10 GB VRAM; this app uses a conservative 10 GB total / 8.5 GB free gate. The current LTX-2.5 system requirements list 32 GB+ VRAM and are outside this adapter. The default profile caps clips at 4 seconds, 12 FPS, 512-pixel long edge and 20 denoising steps. GPU inference still requires validation on the target PC.

## HTTP contract

See the API table in the root README. Uploaded images are accepted as data URLs, size-limited, decoded and verified by Pillow before being written under `uploads/`. Output paths are generated by the server; clients cannot choose arbitrary filesystem paths.
